# Component and slot property options

`src/macros/src/prop_options.rs` owns the `#[prop(...)]` grammar used by both
component and slot expansion. It parses with the already-required `rust-syntax`
AST parser; it does not parse Rust expressions by splitting strings or tokens.

## Boundaries

- Shared options: `optional`, `optional_no_strip`, `strip_option`, `default`,
  `into`, and `attrs`.
- Component-only options: `name` and `marker`. Slot parsing rejects these rather
  than accepting options that slot expansion cannot implement.
- Flags accept their bare name, `= true` / `= false`, and parenthesized boolean
  values. Defaults accept Rust expressions; renamed properties accept string
  literals. Both value options accept `= value` and `(value)` forms.
- Multiple property attributes are merged. Duplicate fields are rejected even
  when their values agree. Mutual exclusion depends on presence, not the value
  of a boolean flag, so `optional = false, strip_option` is still an error.
- Each attribute is parsed before merging it with earlier attributes. Merge
  order and alphabetically ordered conflict pairs keep diagnostics deterministic.
- This module only parses options. Existing component/slot conversion to builder
  settings, emitted token hygiene, and generated runtime behavior remain in their
  respective modules.

The parser replaces generic attribute derivation used only by these two option
records. It does not replace shared Rust token/AST libraries or combine host
procedural macros with browser runtime packages. Removing the only dependency
edge retires the following generic-derive closure after
full dependency-governance checks: `attribute-derive`, `attribute-derive-macro`,
`interpolator`, `manyhow`, `manyhow-macros`, `proc-macro-utils`, `quote-use`, and
`quote-use-macros`. This is a compile-time dependency reduction, not a measured
browser speedup or a claim about elapsed build time.

## Origin and verification

The existing component and slot implementation comes from the retained
Leptos-derived macro source, recorded in
`compliance/licenses/upstream/zxs-web-macro-0.8.19/UPSTREAM-NOTICE.md`.
The previous option parser was generated by `attribute-derive` and
`attribute-derive-macro` 0.11.0. The specialized implementation adapts their
span-joining/fallback diagnostics and deterministic merge/conflict ordering;
these two semantic/design origins remain attributed here after their standalone
package directories are retired. This is not a physical source consolidation:
no original function/module bodies were copied into the macro package. Their original licenses/notices
remain under `compliance/licenses/upstream/`, source/provenance under
`compliance/provenance/`, and documentation under `docs/upstream/`. The original
`docs/traits.html` rustdoc fragment is retained byte-for-byte under
`docs/upstream/attribute-derive-0.11.0/docs/traits.html`; its relative links are
upstream rustdoc placeholders, not generated local documentation. No generic
parser, interpolation, or proc-macro utility implementation is transferred from
the other six packages.

The project-specific parser is checked against behavior captured from the
previous implementation, not an additional generic parser dev-dependency.
The test corpus covers accepted syntax, malformed input, explicit false flags,
ordered option pairs, duplicates within/across attributes, and diagnostic
precedence. Project-authored parser tests and fixtures live under `test/view-macros/unit/`,
separate from the attributed imported tests under `test/macros/`.

### Validation evidence (2026-10-23)

Before removing the old dependency, 269 inputs were evaluated by both old and
new parsers in both component and slot modes. Successful option values,
diagnostic messages/counts, and diagnostic source spans matched for all 538
mode/input combinations. The transient legacy derives were then removed;
`prop_options_cases.rs` retains their captured expected results without retaining
any dependency on the old parser. Focused span assertions remain alongside the
corpus. The reference is the code at `794c3514`.

After edge removal, `cargo test --offline -p view-macros` passed 19 unit tests
and 26 documentation tests. This verifies the retained macros and consumer
context as well as the grammar tests. `cargo check --locked --offline -p web-app --target
wasm32-unknown-unknown` also passed, checking the real browser consumer. No elapsed-build or application-performance claim is inferred
from these correctness checks.

The integrated consumer gate now runs the canonical parser tests with mandatory
name discovery, alongside actual full-Rust-AST, bindgen, terminal-output and
parser consumers. It no longer keeps attribute-derive alive solely for a probe.
`cargo clippy --locked --offline -p view-macros --all-targets -- -D warnings`
passes. The temporary parsed-value enum boxes only its default-expression AST,
avoiding a large payload in each boolean/name slot; the public option shape and
captured parsing/diagnostic behavior remain unchanged.
