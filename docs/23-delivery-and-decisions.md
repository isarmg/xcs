## 23.1 分阶段交付

| 阶段 | 主要内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0 | 完整版本、历史域、用户盘位来源、完整格式/API schema、发布证据模型及 Samba 桥接样机 | 规范向量、状态机和命名通过；11.11 样机证据齐全；SLO 在测试前登记，缺项不得冻结协议 |
| P1 | 本地完整文件、指定分层路由、三成员日志、基础授权/配额/设备隔离、CLI 与离线工具 | 完整提交、故障、PUBLICATION 重放、索引重建和单盘导出闭环；越权、资源上限及第二写者拒绝通过 |
| P2 | 自研 App 业务客户端核心，以及独立 Samba 桥接、主分支和缓存一致性 | App 业务 API 与 SMB 接入分别可用，两个入口并发及失败处理可验证 |
| P3 | 分支记录与首写、历史另存、文件分支合并及节点标签 | 创建只登记冻结来源；实际写入形成 FULL；合并确认输入／结果／归属并同步目录；标签继承和批量原子发布；旧画线仍仅记录关系 |
| P4 | 历史内容清除、节点保留和独立历史树拆分 | G/H/T 用例通过，两树隔离后能分别恢复 |
| P5 | 六平台自研客户端、Web、CLI 完整管理界面，扩展授权策略、容量、盘位换盘和拓扑迁移 | 任务与保护状态准确，固定来源不越界，维护恢复通过；基础安全能力已经在 P1 验收 |
| P6 | 六平台 App 与 SMB 验收、桌面外部编辑、移动端后台及断网处理 | 客户端能力、名字往返、按需读取、未保存内容保留及错误展示通过 |
| P7 | 范围缓存、预读、并行复制及后台调度优化 | 正确性继续通过，基准可复现，未改变全量独立性 |

阶段内可并行准备平台样机，但不等待全部 UI 建成才验证 Samba 对接。P0 重点验证完整操作覆盖、不同文件并发、临时替换、保存失败、身份代理以及缓存失效。无法证明核心保存边界的普通目录共享不作为交付替代。

首个可评审里程碑为“完整提交 → 故障 → 结果收敛 → 索引重建 → 内容核对 → 单盘导出”，随后增加“SMB 主分支保存 → 历史状态登记分支并按实际写入保存 FULL → 指定版本合并连线 → 删除旧内容保留图 → 拆分两树独立恢复”。源码和实际证据见[实现报告](reports/implementation.md)，阶段门槛仍按累计要求验收。

阶段进入条件是累计门槛。格式、发布证据或权限模型改变时，重跑受影响的早期验收；后期 UI 完成不抵消 P0/P1 的失败项。真实平台样机可提前开展，完整跨平台验证仍按 P6 逐组合交付。

## 23.2 关键取舍

| 决策 | 收益与代价 |
| --- | --- |
| App 与 SMB 分别接入 | App 自行实现并通过业务 API 提供完整功能；SMB 由 Samba 及服务端桥接独立提供基础访问，两者共用存储核心 |
| SMB 固定主分支基础访问 | 日常操作目标明确；历史与分支管理另走 App、Web 或 CLI |
| 六平台自研 App | 桌面与移动 App 均自行实现，统一业务契约，界面及系统交互分别适配 |
| 内容版本只 FULL、分支先记录与来源引用 | 创建不复制来源；实际写入才付出独立完整版本成本，旧内容清除不破坏已写新版本 |
| 历史另存只保存实际写入 | 新分支中未写文件保持父版本引用；旧节点和主分支保留，画线不带回内容 |
| 每盘完整普通文件 | 可独立读取本盘内容；不以内容共享降低独立副本成本 |
| 用户指定分层来源 | 各盘职责确定；目标满盘时不能自由均衡，需用户换盘或迁移 |
| 稳定盘位与物理绑定 | 换盘保留职责；需代际和旧盘隔离，元数据成员另外验证 |
| 文件合并与旧关系标记分开 | 合并显式采用正文并推进相关引用；MergeLink 只保存固定关系；二者均不自动拼接或复制正文 |
| 标签和合并采用元数据节点 | 标签快照可继承、节点可复用，正文及原证明保持不变；混合节点图需独立无环验证 |
| 每盘独立备份前缀 | 前缀由用户决定，绑定稳定文件身份；既有版本补保护按候选归档证明，主盘移动不重设路径 |
| 版本父边与标记边分开 | 内容保存和后代范围明确，合并标记不改历史演进或产生读取依赖 |
| 删除内容保留拓扑 | 血缘继续可见；节点不保证字节可恢复，元数据仍增长 |
| 切点全部后代独立拆分 | 两树可分别管理恢复；需复制、重新编号及跨界关系标记处理 |
| 两成员决定、三成员确认 | 保留单盘失效后的恢复证据；不自动降级新写入 |
| 文件级占用、分支发布串行 | 多 SMB 用户可编辑不同文件；同文件及相关目录冲突明确处理 |
| 统一核心、命名和保护规则 | 各入口行为一致；入口和第三方应用错误展示仍需单独验收 |

## 23.3 待验证边界

Samba VFS 的目标版本、操作覆盖、同步及关闭错误传播、SMB 租约与缓存一致性、跨会话文件锁和多文件目录发布都须样机和真实应用验证。受保护写入的延迟和容量表现不能从普通 Samba 性能推断。

全量分支峰值空间、合并连线持久化及拆分时的跨界标记处理、删除内容后的派生缓存清理、固定来源满盘行为、同角色换盘及三成员恢复协议，均需模型、测试向量和真实故障材料。移动 App 的后台、离线和外部应用写回单独验证；独立 SMB 入口的连接、保存和断网行为另行验证。

系统实现、协议模型、性能及故障恢复须按验收标准交付可验证材料。盘格式、协议、命名和任务状态机分别版本化，不静默破坏旧客户端或恢复工具。

<a id="s23-04"></a>

## 23.4 规范边界

产品要求以[第 01 章](01-requirements.md)为入口，不变量以[第 02 章](02-concepts-and-invariants.md)为准；保存及发布证据由[第 10 章](10-transactions-and-recovery.md)定义，入口映射由[第 11 章](11-write-semantics.md)定义。操作手册只说明使用顺序，不另定义一套行为。修改规则时同时更新相关契约、样例和验收映射。

## 23.5 状态、证据与规范维护

设计状态与实现证据使用两列记录：设计可为“拟定／已冻结／被替代”；证据可为“未实现／已实现待验证／已验证”。已冻结表示规则经过评审并有固定格式、兼容约束和模型证据；已验证必须注明构建、环境、用例及报告位置。静态文档检查和部分 schema 通过不使整个系统变为已验证。

| 范围 | 设计状态 | 当前证据状态 | 冻结或验证所需材料 |
| --- | --- | --- | --- |
| R01～R17 产品要求与 I01～I20 不变量 | 规范基线，尚未整体冻结 | 核心、API、CLI、Web、原生宿主和桥接已有实现；部分集成已验证 | 具体代码与证据见[实现报告](reports/implementation.md)，第 22 章逐项验收尚未全部完成 |
| 发布证据与恢复协议 | 实验实现，未冻结发行格式 | 三成员日志/发布闭包、断点恢复、索引丢失重建、历史成功后内容损坏、系统盘恢复及显式永久损失降级恢复已有集成证据 | 补真实设备故障、成员更换/隔离与更广恢复矩阵；不能将临时目录模拟盘称为物理保护 |
| 核心机器可读契约 | 部分草案 | Rust 严格编码与校验器、固定向量、真实保存响应 schema 校验已执行 | [契约附件](contracts/README.md)继续列出未覆盖对象；完整公开路由与盘格式仍需逐项冻结 |
| Samba 与六平台能力 | 目标 SDK/平台边界分别记录 | 本机 RPC/FD、目标 SDK 的 VFS 编译加载及官方 SMB3 客户端用例、真实 Web 浏览器通过，Linux 原生宿主编译链接通过；其余 SDK/真机仍待验收 | [App 矩阵](../apps/README.md)、[SMB 边界](../integrations/smb/README.md)及真实互操作材料 |
| 配置约束、资源与性能预算 | 已实现部分硬限制，SLO 未冻结 | 固定路由满盘拒绝、第二写者拒绝、上传/工作区/条目上限及部分恢复测试通过 | 补细粒度配额、迁移换盘、安全卸载、资源压力与性能基准 |

每项结果使用[验证报告模板](templates/validation-report-template.md)，至少记录需求/不变量/用例 ID、设计修订、代码与工具版本、输入、目标、结果、原始证据位置和限制。失败、未执行和不适用分别登记；不适用必须有能力范围依据。证据缺失保持待验证，不能用“文档规定必须”代替执行结果。

现有 25 章保持稳定锚点；同一规则只在主规范完整定义，其他章节引用并补充本章影响。格式或规则修改记录原因、影响范围和迁移要求；历史版本保留为历史材料，不与当前主规范并列成为权威来源。
