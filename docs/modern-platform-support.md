# 现代消费级软硬件支持与优化边界

本文约束第一方产品的支持范围与优化方向，不将编译通过、能力检测或测试脚本存在等同于设备验收。项目尚未正式发布，不另设产品兼容版本线，也不承诺旧客户端、旧协议或旧格式兼容。

## 产品入口与原生目标

- 保留 Linux amd64 服务端、服务启动和运维 CLI，以及独立 Samba → 本机桥接的 SMB 入口；原生构建和验收目标为 `x86_64-unknown-linux-gnu`。其他 ABI 的必要共享实现不是已验收产品目标。
- 桌面与移动设备使用 Web 或系统 SMB 客户端；不再开发原生桌面 App、移动 App、WebView 宿主或安装包。移动浏览器仍在 Web 评估范围内。
- 存储仍遵守[逐盘独立 Btrfs 与完整性要求](08-full-storage-and-disk-format.md)。安全路径操作依赖可用的 Linux `openat2` 及所需解析限制；平台层立即探测，失败不降级为普通路径访问。部署时还须检查容器或系统策略是否允许该能力，不能仅凭内核版本判断可运行。本文不另造未经验证的最低内核版本。

## Web：按能力准入，按设备验收

当前稳定版 Chrome、Edge、Firefox、Safari 是现代 Web 的预期评估对象，不是无条件支持清单；不设置未经验证的“最近两个版本”承诺，也不通过浏览器品牌或桌面／移动标识推断能力。

当前实现采用以下边界，具体行为见 [Web 组件](components/web.md)和[校验下载设计](architecture/browser-downloads.md)：

- Web 产物为 `wasm32-unknown-unknown`，构建要求 WebAssembly SIMD（`simd128`）；下载要求 HTTPS 安全上下文和可用的单调 Performance 时钟。缺失必要能力时给出明确错误，不引入旧浏览器兼容路径。
- 校验下载需要事务式保存选择器，或可写 OPFS 私有磁盘暂存能力。选择器写入先校验长度与 BLAKE3 再提交；OPFS 路径写入及回读校验后，由用户显式导出。权限拒绝不等于可以改用另一个保存目的地。
- OPFS 导出只是交给浏览器，不表示目标文件已经保存完成。配额、可用空间、权限、浏览器存储策略和临时文件清理仍可能影响结果；存储估算不是容量保证。
- 两条磁盘路径都不可用时，在获取正文前拒绝下载；即使文件很小，也不使用整文件 ArrayBuffer、WASM 缓冲或 Blob 拼接作为兼容回退。独立文本预览继续限制为 2 MiB，不扩大为整文件预览。
- 应用层保持有界分块及背压；浏览器和操作系统内部缓冲不在该边界的保证范围内。不能由此宣称浏览器进程总内存恒定。

上述路径存在于当前实现中，但 Safari、Firefox 及移动设备上的真实保存、配额失败、取消、退出清理和大文件运行仍需逐项实测，不能据此宣传已全面支持。浏览器验收须记录实际版本、设备、操作系统、启用的磁盘路径及结果；真实 SMB 客户端互操作另行验收。

## CPU、内存与 I/O

- 原生 CPU 优化保留现有运行时 CPUID／操作系统能力检测与分派，包括可用的 AVX-512、AVX2 等实现；不把 AVX-512 设为产品最低要求，不将 `target-cpu=native` 作为通用发布构建设置。WASM SIMD 的目标选择不应改变原生分派。
- 已讨论的 32 GB 服务端内存是配置背景，不是经验证的最低内存要求，更不是预分配缓存的预算。继续使用有界工作缓冲，不为本轮优化扩大应用缓存；利用操作系统现有页缓存，而非复制一套整文件缓存。
- 优先减少复制、分配与无效读取，保持流式处理、背压和有界并发。并行 I/O、散列与复制的收益须在真实磁盘、网络和并发负载下测量，不能仅凭消费级硬件名称推断吞吐提升。
- 基准分别记录文件大小与数量、磁盘类型、客户端、并发数、冷／热缓存条件、吞吐、延迟和峰值内存；尚未测量的性能不作承诺。容量和准入继续遵守[容量、配额与性能预算](19-capacity-and-performance.md)。

## 不因“现代化”删除的约束

配额与资源准入、取消和超时、会话隔离、长度与散列校验、原子发布、权限检查、无障碍交互、可诊断错误及失败清理都属于正确性要求，不是旧平台兼容负担。任何优化必须保留这些边界和对应回归测试。

本策略只收敛第一方产品范围，不据此重命名第三方源码、删除许可证或来源记录，也不把依赖库中的平台分派误当作必须清除的兼容层。
