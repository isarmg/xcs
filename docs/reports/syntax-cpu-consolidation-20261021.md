# 语法解析、源码格式化与 CPU 检测整合

## 实际合并

| 退役实现 | 存续上游身份 | 调整 |
| --- | --- | --- |
| syn 2.0.119 | syn 3.0.9 | 所有活动消费者切换，显式适配 AST 类型变化 |
| prettyplease 0.2.37 | prettyplease 0.3.0 | 与配套解析器共同升级，保留格式化输出测试 |
| cpufeatures 0.2.17 | cpufeatures 0.3.1 | Argon2 使用共享检测器，保留 AVX2 与操作系统状态判定 |

这是依赖图与实现的真实合并，不是给两份版本改不同名字。八个源码文件和十个依赖表经精确变更校验，修正 tracing 安全性标记与 impl Trait、axum 接收者、typed-builder 类型/默认值与 mutator，以及 SQLite 函数指针 AST。

退役 94 个源码文件，合计 2,087,940 字节，及 46 个外置测试文件。来源清单保留最后逐文件摘要与退役原因；原始版本、归档、许可证和历史字节保留，不将实验工作区的锁文件覆盖到根工作区。整合后的活动源码为 320 项、退役 82 项、已替代 2 项。

## 验证边界

- 隔离候选的真实消费者检查、浏览器 WASM、Argon2 no_std 与实际 SQLite 扩展绑定生成通过。
- 纳入 foundation CI 的维护门禁覆盖 67 个 typed-builder 用例、15 个 Argon2 PHC 用例及四个运行时追踪/格式化/CPU/SQLite 用例，合计 86 个通过；五个原有忽略用例保持原状。另一个无类型泄漏目标检查编译，不虚报运行测试数。
- 使用真实 C 编译器资源头与 SQLite 原有头文件生成绑定，不伪造标准头，也不只检查文本。
- 借用接收者处理器必须以预期诊断失败；测试运行器拒绝额外错误和警告。
- 三个 Python 回归检查测试目标、特性和构建配置，防止可选用例被错误关闭后出现零测试的假通过。
- 主工作区重新运行完整维护门禁、静态门禁、源码与元数据验证，以及格式/Clippy/原生全目标/发布 WASM 质量检查，全部通过。
- 当前合并与后续功能命名分开提交；存续组件计划命名为 rust-syntax、rust-source-format、cpu-feature-detect。本报告的合并不代表后续命名已完成。

来源和原始版本见 [Rust 来源清单](../THIRD_PARTY_RUST_SOURCES.md)，命名规则见[命名规范](../NAMING.md)。最终远端验收以本批对应提交的 CI 为准。
