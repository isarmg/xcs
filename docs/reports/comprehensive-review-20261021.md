# zxs 全面复审与修复记录（2026-10-21）

本轮从最新 `575bd809140222dcf79abe5007b712470b2c4583` 重新检查，不把上一轮 13 项 CI 通过视为不存在其他问题。审查覆盖引擎发布与恢复、HTTP/认证、SMB/FFI、Web 会话生命周期、CLI 配置、维护依赖的验证工具、发布输入以及当前文档。

这不是对所有第三方算法逐行证明，也不是物理设备掉电、拔盘或生产部署验收。SQLite、journal／不可变对象／files 权威模型、G4 几何和字体保持不变；原生范围仍为 Linux amd64，必要浏览器 WASM 单列。

## 已修复问题与证据

| 边界 | 原问题 | 修复与回归 |
| --- | --- | --- |
| 凭据预算 | 写入可超过读取端 4 MiB 上限，成功操作后重启失败 | 写盘、临时文件和备份发布前检查序列化大小；拒绝后账号、generation、会话、旧文件保持不变；有效权威快照可替换超大本地缓存，仍拒绝链接或不安全权限 |
| 外部 Origin | 大小写、默认端口或 IPv6 等合法配置与浏览器规范 Origin 不匹配；大写 HTTPS 可漏设 Secure | 配置校验、同源比较和 Cookie 共用规范化结果；拒绝错误 scheme、host、port 和 `null`，不扩大跨源权限 |
| FileManager 准入 | 非字符串 path 静默当根；错误请求先持久创建 disk-root | 区分读取、写入已有目录与允许初始化；提前校验字段、名称、操作号、目标及根基线名；缺失删除目标、跨命名空间目的和已占操作号不先建根 |
| 元数据恢复 | 每块盘分别损坏不同页面时，完整认证闭包仍因单盘不完整而恢复失败 | 从日志绑定的同一 snapshot 根按精确页面摘要逐对象选取副本；读验证不修盘，完整闭包通过后才进入恢复修复 |
| purge 收尾 | 首个 metadata member 的坏 candidate／publication／snapshot／seal 副本遮蔽健康副本 | 复用认证副本解析，不任取首盘，不以多数票替代精确摘要 |
| 本地证明 | 非权威本地 proof 损坏阻断完整权威发布恢复 | 从已验证发布闭包重建；冲突 regular 文件先持久化隔离保留；链接、不可验证闭包和 I/O 错误仍拒绝 |
| 容量预算 | split 后已物理移除的 MIGRATED 正文仍计入占用 | admission 和磁盘展示同时排除 MIGRATED；真实 split 后在受限预算内继续保存的回归通过 |
| 恢复成员选择 | 两个池各自满足配置门槛时按字典序任取一个 | 拒绝多候选配置和外来成员；检查输入盘封印及 metadata 身份；单一有效池继续恢复 |
| CLI 注册草稿 | 无关 `--root` 可绕过 live 配置保护，非法新增磁盘可写入草稿 | 依据实际配置和磁盘身份判断未初始化状态；有界、owned、无链接读取；候选共用纯配置校验后才备份及替换；拒绝别名、已封盘、路径重叠及非法拓扑 |
| 拓扑校验 | `source.level + 1` 在极值输入溢出 | checked_add 返回配置错误；共享纯校验不创建磁盘目录 |
| Web 退出 | 服务端撤销待确认期间仍可新发写操作或下载 | 动作和控件复用统一会话准入；凭据仅供撤销重试；失败重试和重新登录恢复行为保留 |
| SMB 删除 | unlinkat 丢失 flags，无法区分删除文件与目录 | 客户端、wire、冻结工作区树验证及 errno 保持 unlink/rmdir 类型闭环；旧模糊 delete 请求拒绝 |
| SMB 不确定结果 | namespace 提交错误会 Abort，成功响应丢失后原操作号未知 | 客户端预分配 ID，服务端校验并沿用；传输错误保留 ID；提交前同步恢复关联，结果不确定不 Abort；已有、活动或有恢复记录的 ID 拒绝复用，错误不提示自动重放 |
| 发布输入 | 损坏 WASM、未登记输出或符号链接仍可打包，事后 checksum 只证明坏包自身 | Rust 构建器和 Python 验证器共用自纳入哈希的输入范围；核对输入／输出集合和摘要，拒绝链接、特殊文件及非法路径，打包私有已验证快照 |
| 后端矩阵 | 继承的 encoded rustflags 覆盖脚本选择，多个标称后端实际测同一个 | 四个矩阵在启动前拒绝 encoded flags（包括空值）和非空外来 RUSTFLAGS，再显式设置受控 case flags；补负向回归 |
| 来源闭包解释 | 工作区统一 features 后的可达集合被误解为精确单入口运行图 | 保留安全保守超集，增加回归及明确限制；不能单凭该集合裁剪源码，不引入第二产品 workspace／锁文件 |

原问题通过定向失败回归、真实临时磁盘夹具、socketpair 帧传输或独立负向打包夹具验证。新增协议尚不支持的错误不被用来冒充原误删证据；SMB 原 delete 反证确实导致目标删除并发布。全部持久化故障测试使用临时目录，不操作真实用户盘。

## 验证及保证边界

- 本地完整 engine 测试：260 个 unit、32 个 integration 通过，2 个既有 ignored 不计为通过：超过 64 MiB 的分布历史用例由 workspace 专项入口另跑，人工延迟测量本轮未执行。
- 认证与 Origin 定向 33 项、FileManager 5 项、admin 27 项及配置纯校验 2 项通过。
- Web／界面／宏／浏览器工具宿主及文档测试合计 239 项通过，WASM release check 和相关严格 Clippy 通过。慢退出真实 DOM 回归已加入现有 browser-smoke，不以编译通过替代浏览器执行。
- SMB 协议 10 项、server scoped 31 项及独立 namespace 14 项通过。独立计数包含重叠覆盖，不相加成总用例数；本地命名 Unix listener 受执行环境限制，socketpair 并不冒充真实 Samba SDK 验收。
- 发布验证包含损坏、缺失、额外输出、输入变化、链接和快照隔离回归；矩阵环境和来源范围另有负向测试。整合静态门禁及当前契约检查通过。
- 最终生产 WASM、真实浏览器、全工作区、foundation 完整矩阵、严格诊断、安全扫描和真实 Samba SDK，以承载本轮最终修改的精确提交 Checks 为准，不继承上一轮绿灯，也不预填尚未完成的 CI 结果。
- 契约检查会单列尚未生成的历史证据附件；这些链接不能被解释为已有测试产物或实际环境验收。

仍需准确区分的设计边界：

- FileManager 已阻断已确认的字段／目标错误及可预检冲突，但 lazy root 初始化与后续业务发布不是一个跨阶段原子事务。后续容量、物理 I/O 或发布失败不能用删除已发布初始化来伪造回滚。
- SMB 提供明确操作身份和不确定结果查询，不提供跨客户端自动成功重放或端到端 exactly-once；调用者不能收到错误后直接生成新 ID 重试。
- 已准入的读取计划不承诺追回已经开始传输的字节。Web 阻止的是退出开始后的新业务操作，不将其说成撤回历史网络请求。
- SQLite 仍是可重建派生视图；跨盘恢复仍要求精确认证闭包。没有新增未知数据自动 GC、通用多数票恢复或任意坏文件覆盖。
- 本轮未宣称吞吐或内存性能提升，未执行真实设备掉电／拔盘，也未发布版本、部署服务或改动生产配置。
