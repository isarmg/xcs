## 文件管理、容器与分支

文件分支先发布 pending_file_versions 冻结引用，不复制来源正文、不新增 FileVersion 或冻结来源引用文件；兼容整树创建也只登记元数据。目录分支组合共享文件分支，显式创建才增加稳定命名对象；修改文件或切换子项生成不可变 DirectoryTree 并推进原 head，不自动增加命名分支。实际写入才生成独立 FULL，零字节或同来源字节首写仍形成真实版本。历史另存只保存实际 staged 文件。

文件管理继承投影明确返回可见父 `version_id` 和大小，附 `materialized:false`、`inherited:true`、`own_version_id:null`，`content_state:"PENDING"` 只表示归属，`visible_content_state` 是父版本实际内容状态。父可读时 Web 预览/下载和 SMB 读取正常；范围编辑保留父未改范围，首次实际写入后读取自有 FULL。目录逐文件组合继承与自有内容，旧快照始终保留其冻结父版本。活动继承和工作区固定所需父正文，首写后且无其他引用才能清理。泛型 Entry 字符串和旧对象规范编码保持兼容。最新规则及验证见[分支继承说明](lazy-branches-20261019.md)和[继承语义证据](../../tests/evidence/inherited-branches/README.md)；此前禁止读取的占位方案以及更早创建即复制正文的结果都作为历史快照保留，不当作最新语义验收。

默认页面为“硬盘目录 → 文件夹/文件”，选择条目的“详情”会进入独立的顶栏菜单页面，返回时保留原目录与搜索条件；状态和历史记录也有独立页面。磁盘不作为分支；文件详情围绕稳定 `file_id` 展示分支、完整历史版本及备注。文件列表和工具栏、自定义选择器、登录字号、中英文业务文案已按当前需求重做，文件功能见[文件管理证据](../../tests/evidence/file-manager/README.md)，详情页面布局与操作见[独立详情页证据](../../tests/evidence/details-page/README.md)；早期 Web 截图保留为旧版记录。

目录分支的稳定 ID、名称与不可变子树分开；每次修改把新子树连向旧子树并推进 head，旧树固定历史文件版本。目录改名保留 entry_ 身份，旧树保留旧路径，选择按 file_id 映射当前条目。目标组合缺少当前文件时整次拒绝。根默认组合可由普通有写权限用户选择，并供稳定 SMB 主命名空间读取；App 仍独立走 HTTPS API。完整规则见[分支与目录子树](lazy-branches-20261019.md)。

新正文位于真实文件容器目录，内部按文件序号、UTC 时间和散列短前缀命名。改名仅重命名容器，历史内部文件名不变；历史下载使用当前容器名称。文件备注和版本备注分别持久化且受权限和长度限制。不可变版本证明仍在独立版本目录，容器缓存可从已发布状态重建。旧正文布局保持读取兼容，本次没有隐式搬迁全部旧载荷。

文件历史版本现按真实 `source_version_ids` 形成版本树，父到子使用箭头连接；每个节点只显示日期、备注和编辑备注／创建分支三行。来源字段仅含同文件、同授权历史内真实较早版本，多父关系保留，无来源作为根，不按日期补造关系。前端按反向拓扑分层：各分支最新叶子在最上层，旧父版本逐层向下，不等长分支的最新节点也保持置顶；箭头保留旧父到新子的含义并向上指向新版本。同层按日期及分支位置稳定排列，稳定复用节点，备注第二行原位编辑，连线随节点尺寸更新，跨层边沿侧边通道避让节点；普通手机仅在树内滚动，不增加浏览器过度缩放处理。验收使用独立临时池中的真实分叉、备注和创建分支，见[版本树检查](../../tests/evidence/version-tree/README.md)。

基础监测使用真实主机采样，CPU 首样本为不可用基线，后续按间隔采样；内存及容量使用十进制字节字符串。CPU 功耗来自 Linux RAPL package 能量差，磁盘功耗仅采用归属该物理盘的 hwmon 功率传感器；缺失为不可用，不使用 TDP 或使用率估算。磁盘容量来自各路径所在文件系统，模拟目录可能共享同一物理容量，且没有独立功耗。独立后台每 5 秒采样，最近 1 小时保存 5 秒点、31 天保存分钟聚合点；缓存重启恢复且不改变业务发布序列。状态页显示实时数值和范围历史折线（1min/30min/1h/24h/1month），缺失采样保留间断。监测不枚举进程或网络；菜单中的文件历史记录仍来自已提交的实际文件操作，二者分别保存。

文件及版本备注的新值最多 128 个 UTF-8 字节，前后端均校验，禁止换行和控制字符。Web 的备注、新建文件夹、重命名及创建分支均原位使用下划线输入，Enter 保存，Esc 或失焦取消；清空备注可提交。已删除对应文本输入弹窗代码，旧备注不截断。状态卡固定 3:2，桌面四列、手机一列，不足四张时不拉伸。菜单和文件工具行沿用紧凑列表的文字留白，不再横向均匀散开。最新验证见[原位编辑与监测记录](../../tests/evidence/inline-monitor/README.md)。

## 保存、恢复与隔离

完整复制显式读写全部字节，目标使用新 inode，不使用硬链接、reflink 或去重。中途失败不会把未完成输出当作完整文件发布。路径按目录句柄打开，拒绝祖先与终点符号链接；已有非私有管理目录被拒绝，不通过自动改权限接纳。

未决候选缺少副本时，恢复会核验固定路由内的完整文件、工作区保留代际、已发布同摘要版本及已知隔离材料。存在正确字节时，将损坏目录无覆盖移入隔离区，再按原版本 ID 和原路由完整重写。不会通过更换候选或自由选择目标盘掩盖故障。

发布依次形成候选、三成员 ACCEPT、FINALIZE、每盘提交证明、三成员 PUBLICATION、发布同步回执封印、本盘发布证明，最后原子应用 SQLite 索引。离线证明包含实际日志帧与哈希，可以独立核验各阶段回执。仅单份 PUBLICATION 且缺少同步封印时保持原可见 HEAD；已有历史正常发布不会因后续内容损坏被改写成“从未保存成功”。当前健康单独计算。

上传保留显式代际。相同代际只接受相同长度及摘要的字节；旧代际拒绝，新代际保留旧完整暂存文件。封存后的清单不可修改，提交摘要绑定工作区、分支、预期 HEAD、fencing token、拓扑代际、放置和操作身份。失败后查询或重试原操作，不能生成新操作覆盖未决结果。

业务授权在发布前复核。同一文件被工作区占用，互不相交文件可以在分支串行发布时重核版本并继续。读租约阻止历史内容被清除，租约覆盖内容流的实际生命期。显式清除先发布状态，再写本盘墓碑及其状态页包含证明，最后删除字节；离线清除残留在原盘返回后继续处理。

三成员正常事务同时保护认证控制状态。系统目录丢失后，从至少两个一致的原成员配置恢复，重放状态和凭据摘要，重新生成 SQLite，并发现一级盘上的待提交工作区。单盘只负责本盘有效版本的离线检查和导出，不凭一盘推断完整全池最新状态。

树拆分为单独仓库，重新映射文件、条目、版本、提交和分支身份，复制完整历史字节并独立保留 ACL 与策略。外部边转为明确审计边界，不留下空 ID 或普通图中的悬空引用。原共享不自动转向新树；迁出主分支时停止原绑定，新树也默认关闭 SMB，管理员须显式重绑。

无正常发布证据的已决定候选若存在永久内容损失，只允许本机维护入口创建唯一降级恢复计划：要求至少两个原 ACCEPT、三个完整未截断成员日志、当前登记盘身份和写锁齐全，排除所有已知可修复字节及原正常发布材料。操作者显式确认永久损失后，三成员记录恢复隔离及重新保护，发布 `PUBLISHED_DEGRADED / COMMITTED_DEGRADED / BELOW_TARGET`，冻结实际不可用盘位。候选及版本 ID 不改变，幸存文件继续可读。证据不足、只有一个原 ACCEPT 或仍有正确完整字节时拒绝该降级路径；新业务写入不能使用它绕过正常保护。

每棵历史树的恢复清单哈希由候选及发布闭包固定。历史包只包含该树、相关仓库权限/策略、证明和完整文件，不带全局认证控制状态或其他树的展开内容。包导出先构建私有临时目录、核验再无覆盖发布；导入新池后重新复制到用户指定路由并形成新发布。已验证删除原系统与所有原数据盘后，仅靠单包恢复、追加保存和重启读取。

工作区目前明确拒绝上传与删除/改名路径重叠的混合批次，返回 `WORKSPACE_DEPENDENCY_BUSY` 并保留字节；创建父目录后上传子文件可同批提交。此限制避免尚未实现完整交错事件模型时误报成功却删除新上传内容。所有保留上传代际的完整文件均计入工作区字节预算，封存工作区继续计入数量和文件占用。

## 读取与元数据容量边界

当前内容打开路径会先通过 `valid_replica` 调用 `verify_payload`，扫描所选副本的完整文件及校验清单。HTTP Range 只向客户端返回所请求范围，但每次新内容请求仍可能在服务器重新全扫文件；SMB 每次打开文件也会承担这项校验，已打开句柄的后续读取不重复该次全扫。因此，大文件首字节延迟和大量小范围读取的磁盘 I/O 成本尚未优化，不能将 Range 功能通过解释为大文件按需读取性能已达标。后续需要结合不可变版本证明、按块校验与有界缓存验证完整性和性能，仍须实际测量。

状态快照已经分页，单树 `HistoryManifest` 目前仍是包含完整提交、目录快照、版本和策略的单个 JSON 对象。每次持久化会遍历所有历史树，重新构造并序列化清单；未变对象复用相同哈希，历史增长则生成新的完整清单，尚无增量分页或结构共享。这会使保存、认证控制事务和恢复的 CPU、内存及元数据 I/O 成本随历史增长，不能据小规模文件集成测试推断十万目录项、多版本历史的容量表现。

结构化元数据统一使用 **64 MiB** 的读写上限。正常事务在复制新副本和写入 PREPARE/ACCEPT 前，检查实际快照页、历史清单、候选以及完整发布/本盘证明的序列化大小；历史包的组合证明与清除墓碑也纳入检查。超限返回 `RESOURCE_LIMIT`，已发布状态、日志和决定槽位不推进，不生成现有读取工具无法接收的新对象。恢复降级也在写入 REPROTECT 前检查组合证明。该限额约束历史元数据，而非文件内容大小；历史增长达到限额后继续保存会明确拒绝，仍需历史清单分页及规模测试扩展容量。新增边界回归使用可注入小上限验证精确边界与拒绝后状态保持，并对真实发布、历史包和墓碑的落盘大小复核。

静态资源的 ETag 表在服务启动时生成。资源更新应使用固定版本目录并重启服务加载新清单；运行中的 `--web-dir` 必须保持不变。当前不支持直接热替换该目录，否则内容与启动时缓存的 ETag 可能不一致；浏览器证据均在最终资源构建并重启服务后取得。

## 仍需完成与验证

以下项目保持明确缺口，不能因源码和模拟测试通过而视为完整产品已交付：

- SMB 的各平台真实应用保存、write-through/FLUSH 客户端链路、断网重连、多账户部署与缓存一致性完整矩阵；官方命令行客户端通过不能代替这些用例。文件系统时间戳及按保护路由报告容量尚未完整建模，活动写句柄期间的临时替换也不能从关闭后改名测试推断支持。
- Windows、macOS、Android、iOS、iPadOS 的 SDK 构建、真机运行、后台生命周期、外部编辑交接及签名分发；Linux 原生宿主运行和打包也需独立验收。
- 真实独立 Btrfs 设备上的断电、拔盘、内核 I/O 错误、同步持久性和硬件身份测试。生产模式拒绝无法证明独立性的虚拟块设备，不将多个 loop/dm 映射计为不同物理盘。
- 成员更换与旧写者隔离、同角色换盘、已有数据拓扑迁移、安全卸载的完整计划和真实设备链路。
- 显式降级恢复目前仅支持上述严格的全登记盘在线且三完整日志条件，不能代替缺失元数据成员的更换协议。恢复包导出要求拟导出的可用内容都能完整核验；不把缺失文件静默跳过为完整备份。
- 目录缓存与按段预取、跨平台后台调度、每账户精细配额和完整容量/性能 SLO。当前已实现全局工作区/文件/条目上限、固定路由容量预检及有界 HTTP 上传；不声称性能基准已达标。

接口不支持的操作必须明确拒绝，能力响应只声明已经实现的功能。第 22 章全部验收仍需按实际环境逐项登记，不能将此报告作为“所有功能完成”的证明。
