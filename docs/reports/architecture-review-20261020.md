# 架构复核与修复（2026-10-20）

本轮从提交 `6d0b47f` 重新检查自研模块及端到端调用链。目标是消除入口间行为分裂、补齐真实调用路径，并让阻塞工作和资源所有权明确，而不是单纯拆分文件。SQLite 仍是可重建索引；不迁移或清除用户池，不降低发布保护、权限、摘要或落盘要求。

## 本轮架构调整

- 工作区提交：同步、分阶段执行和 wire 重放复用权限、操作归属与请求摘要校验。恢复使用精确匹配的持久请求材料，不能因“某操作 ID 存在”就关闭另一工作区。
- 原生上传：选择文件得到受会话约束的一次性能力标识，WebView 不取得文件系统路径或 bearer。原生侧固定已打开文件句柄，哈希准备与发送分阶段；发送前重新检查工作代次。网页与 App 的两个上传入口进入同一队列，但字节传输分别走浏览器和原生实现。
- 原生会话：凭据寿命与工作代次分开。退出开始即让旧工作失效，但保留退出失败重试所需凭据。已经发送的请求不能因此被描述为已撤销。
- HTTP 执行边界：阻塞认证、重试前缀验证和持久化操作不直接占用异步执行器。后台任务保持准入及文件所有权，取消请求不能提前放开同一上传的互斥边界。
- 暂存文件：未被记录引用的请求文件由 RAII 清理；记录发布后所有权转移，后续目录同步失败不能误删记录已经引用的字节。
- CLI 草稿：登记备份保留配置的完整文件名，避免不同扩展名草稿覆盖同一备份。需要进入 JSON 的路径在修改前校验，避免修改成功后才因输出序列化失败。
- 公共界面：恢复普通输入的键盘焦点可见性；轮廓绘制降级不再隐藏选择菜单；格式化参数只替换原始模板占位符，不递归解释参数内容。

## 审阅边界

按模块检查存储发布与恢复、工作区、索引与历史，HTTP/SMB 认证和传输，原生连接/缓存/文件打开，Web 状态与上传队列，共享运行时和样式，以及 CLI、契约、命名、认证和构建发布脚本。部分大型几何/宏实现与测试生成器采用重点路径及回归检查，不声明逐行审计所有源码。

第三方 Cargo 依赖、字体、Unicode 原始数据及许可证不是本轮改造目标。项目维护的 CSR 代码与其外部依赖分开处理。检查和测试不代表真实移动设备、系统文件选择器、签名分发、物理盘移除或断电验收。

## 验证原则

已确认问题先保留失败用例，再验证修复。原生上传用受控 HTTP 服务检查真实请求与文件句柄；会话测试固定异步阶段并验证过期工作不能继续。界面源码规则测试仅作为快速回归，真实焦点和菜单可见性另外接入 Chrome 烟测，不能用字符串匹配替代浏览器结果。

服务端慢 I/O 诊断使用受控延迟注入，说明异步执行器是否被阻塞，不作为真实磁盘吞吐或端到端生产性能承诺。完整测试与最终 CI 结果以对应提交的运行记录为准。

本地整合验证：核心 200 项单元测试及 30 项集成测试通过（另有 1 项忽略）；客户端 20 项、CLI 20 项、原生桥接 32 项、Web 应用 101 项及运行时/组件 34 项通过，WASM 检查通过。服务端 73 项单元、26 项 HTTP 集成及遥测集成通过。根工作区完整测试中，平台 2 项及 SMB RPC 1 项在创建 Unix socket 夹具时被沙箱 `EPERM` 阻断，未修改或跳弱测试；原生宿主本地缺少 GLib 开发库，须另由 CI 验证。文档契约检查通过；新增 Chrome 可见性场景只在实际浏览器执行成功后才算通过。

在本地受控探针中，给重试前缀读取或 retained 记录同步注入 400ms 延迟，原实现的 10ms 定时器分别约 401ms、403ms 才触发；移出异步执行器后约为 12ms。认证备份注入 500ms 延迟时，认证请求仍正确等待锁内操作完成，但同一执行器的定时器从约 515ms 恢复为约 13ms。这只证明隔离阻塞，不表示省略认证等待或同步落盘。

## 保留的验收限制

- Android 等文件提供方 URI 的末段不一定是用户可见文件名。可逆的文件 URL 按路径解码；当前公开插件接口无法提供可靠显示名称的 provider 被明确拒绝，不把内部文档 ID 当文件名。完整 provider 支持与移动选择器行为仍需平台适配和设备验收。
- 上传记录重命名后若目录同步失败，保留可能仍需恢复的旧文件优先于清理空间；本轮没有实现通用断电孤儿回收器。
- 原生宿主编译、受控桥接 HTTP 测试与真实系统选择器交互是不同层次；不得把前两者当作六平台 UI 已完成验收。

原生能力边界见[设计说明](../design/native-upload-boundary.md)，服务端阻塞与暂存所有权的探针、修复和保留边界见[专项报告](server-protocol-review-20261020.md)。
