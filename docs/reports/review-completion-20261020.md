诊断包装器保持 Cargo 参数与原有编译环境，不添加宽泛 `allow`、修改 `RUSTFLAGS`、降低 lint cap 或更换缓存来掩盖警告。已有诊断按实际成因修正；构建脚本和 Cargo 的 stderr 继续可见。质量及发布验证工作流显式准备 WASM 标准库。

闭包描述 normal／build／proc-macro 的解析候选及角色，不表示每个保留文件最终进入产品链接，也不把 aarch64 元数据验证冒充交叉编译。静态全特性边校验同样不等于运行所有可能的特性组合。

## 宏文档和模块职责

`view-macros` 的文档使用真实 `web-interface` 开发依赖作为消费者上下文；该依赖不进入产品运行闭包。适用于当前 CSR 的示例恢复正常编译，负例因实际语法约束失败。常规 Web 入口恢复完整 `cargo test`，同时执行单元、集成与 Rustdoc；没有用 `--tests`、`ignore` 或关闭文档测试规避原有失败。`include_view!` 按消费者根目录解析文件，并通过编译器输入记录跟踪文件变化，接口集成测试使用真实 RSX fixture。

质量说明中登记的参数 API 迁移也已实施：客户端及引擎备份配置、放置规则、保护策略改为具名请求；内部文件节点发布、版本构建、历史边界、元数据预检与演示子节点改为具名输入，单次参考节点直接按字段构造。调用方同步保留认证主体、作用域、预期代数与操作身份；HTTP 字段及持久化语义不因 Rust 调用方式改变。

较大模块按原有职责边界拆分：

- HTTP 生产入口与边界测试分离；存储引擎适配器中的内容交付、线协议转换和授权回归分离。
- Samba VFS 的路径转换、描述符操作和测试分离，已有异步模块继续维护原本的线程、请求生命周期及清理契约。
- 保持 HTTP 业务 API、协议字段、鉴权规则和真实 SDK ABI；公开 Rust 方法签名与仓库内消费者同步迁移，模块拆分不改变业务语义。
