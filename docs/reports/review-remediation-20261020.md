# 静态审阅整改追踪：2026-10-20

审阅意见作为待核实线索，不作为测试结果。本文区分已经实现的修复、仍需推进的架构工作及不能机械采纳的建议；最终验收以对应提交的 CI 和明确记录的测试范围为准。

## 已实现，等待整批 CI 验证

- **框架自维护**：Leptos 同仓依赖族纳入源码、原始发布包哈希、许可证和补丁清单管理。宏事件修饰符按完整段解析；卸载显式清理 owner；启动先发布所有权再通知 ready；UI 异步任务与文档根绑定。G4 几何和绘制源代码不变。
- **字体启动**：功能就绪不再等待字体下载，字体有独立的 pending/ready/failed 状态；字体失败保留可使用的回退字体界面，真正的 WASM/CSS 启动失败仍受保护。原始字体文件不变；延迟、缺失字体和页面释放后的迟到完成由真实 HTTP 故障夹具交给浏览器 CI 验证。
- **元数据增长**：事件从单一 scalar 字段改为有序分页，拒绝重复、缺口和混合表示。快照与历史清单的规范化字节一次准备、多次复用，不再为预检和落盘重复编码。保留历史事件、操作回执和旧数据读取。
- **编码中间内存**：快照逐页借用类型化条目，移除整个 State 的中间 JSON 树；穷尽字段声明与差分测试约束旧 v2 的字节、对象哈希和页面边界不变。临时页面至多 128 个顶层条目，但最终编码对象仍全部保留，不能据此宣称总内存常量化。
- **对象目录**：新哈希对象按两位前缀分片，已验证的旧平面对象直接复用，不迁移或复制历史。两处重复表示必须一致；恢复、离线导出、检查点和性能计数同时覆盖两种布局。
- **登录限流**：显式受信回环代理模式只接收一个覆盖写入的来源 IP，默认忽略转发头。来源限流与账户串行渐进延迟分开，等待不占用全局密码计算槽位；对计数与等待账户数量设上限。需要部署者明确配置代理，代码更新不自动改变现有部署。
- **授权一致性**：核心与服务端使用同一 `RepositoryAccess`/`Grants::allows`。Read 与 Write 独立，Manage 包含两者；账户级准入和管理员判断仍单独执行。
- **后端分发**：75 个操作进入封闭 `BackendAction` 枚举，主分发穷尽匹配。HTTP、SMB 和内部调用统一使用该类型；这不等于全部 JSON 载荷和响应已类型化。
- **持久状态类型**：提交状态与发布保护状态改为明确枚举，使用原有大写序列化值；52 个组合的固定规范化字节与域哈希迁移前后一致。未知状态返回反序列化错误，不以默认值掩盖损坏。
- **损坏状态处理**：目录业务去除未检查的 map 索引及 expect，缺失分支、提交、目录树和文件引用返回错误；回归验证失败操作不发布部分状态。
- **读取临界区**：Tree 请求在当前授权与历史归属检查后捕获独立 DTO，释放引擎锁再编码响应。测试在序列化期间从另一线程获取锁；没有复制整个 State。
- **兼容别名**：删除纯代码层认证兼容导出，直接使用共享凭据 crate；不删除用于已有数据恢复的读取器。
- **文档与配置一致性**：消除重复第 21 章，加入 ADR、架构索引和一次写入流程，清理公开文档私有绝对路径及历史日志排版残留。根 crate 的版本、语言版本和通用依赖约束集中继承。
- **旧探针维护**：26 个历史 JavaScript 模块逐一分类；22 个探针改用显式、可移植的夹具与独立输出配置，4 个 G4 参考文件保持原字节。质量门禁检查语法、路径与清单完整性；不把静态检查冒充历史浏览器重跑。

## 正在验证的质量与安全工作

- 已为 11 个主要第一方 workspace 加入格式与 `clippy --all-targets -- -D warnings` 门禁，维护的 core/macro fork 也单独检查；本地已通过。新增原生回归 harness 由 SDK job 单独编译。少量函数级参数数量 `expect` 及迁移计划见 [质量策略](../../.github/QUALITY.md)。G4 仅在父模块声明标注旧文档 lint 的明确例外，源文件不变。
- 固定 cargo-audit 0.22.2，13 个消费者锁文件与 20 个自维护依赖原始上游身份的影子锁审计已通过。影子锁不会参与构建，新增未审阅公告及遗漏路径依赖均失败。GLib 安全回补与仓库维护的 proc-macro-error2 未维护公告仍明确保留；这不是“零公告”声明。扫描器即使返回 0，只要报告 registry/yank 查询错误也不得判为完整成功，最多重试一次。
- 审计发现的未维护宏依赖与桌面宿主依赖分别处理，不能通过无说明忽略公告声称完成。
- SMB FFI 增加可核实的安全边界与检查，固定 Samba 4.23.0 SDK 的严格 Clippy、7 项真实链接测试与 release 构建已本地通过；另在 30 个新进程中重复并行运行测试，共 210 项通过。宿主 CI 尚待确认，未启动 smbd 或重复历史客户端验收。见[本轮记录](../../tests/evidence/smb/review-2026-10-20/README.md)。

## 尚未完成的架构工作

1. 完整写入仍不是 O(delta)：State 克隆、全量状态遍历、全部历史清单构造和不变对象碰撞校验仍随保留历史增长。事件分页也不取消根引用、页面或发布证明的大小上限。
2. 并非所有读取都脱离 Engine 互斥锁；完整不可变读取视图需要同时处理当前授权、租约、缓存与发布边界，不能仅换成 RwLock。
3. 后端请求/响应的分领域类型化、当前健康状态类型和契约自动生成仍需独立迁移与固定格式回归。操作名枚举只解决分发词汇不受约束的问题；已经迁移的提交与发布保护枚举不代表全部响应已类型化。
4. 目录模块之外的异常状态索引仍需逐域审查；不能把一个模块的防 panic 修复称为全仓完成。
5. 真实设备掉电、拔盘、独立物理磁盘以及原生移动设备验收未由单元测试或 CI 替代。执行前需明确可处置设备及故障注入方式。

## 保留的设计与边界

- 保留 SQLite 与现有权威日志/对象恢复模型，不因审阅建议而替换数据库。
- 不以 TTL 清除幂等回执或历史事件来降低成本；不自动回收历史对象。
- 不将三成员写入要求改为未经设计的降级发布；两成员决策证明与写入准入是不同约束。
- MergeLink 的关系记录与内容分支合并语义不同，不作为“重复旧概念”删除。
- 无旧软件兼容承诺，不代表可以丢弃已存数据或删除必要恢复读取器。
- 自维护 Leptos、G4 及六平台范围遵循当前产品方向，不采纳审阅中相反的收缩建议。
- 分离 workspace 的平台/工具链边界不能简单视为故障；本轮先统一根 workspace 的重复约束，保留各实际消费锁文件的审计。
