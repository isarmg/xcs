# 两份外部评审的选择性改进

## 范围与原则

两份评审基于不完整或不同提交的源码导出，其中缺少测试与合规资料。此次以完整仓库和实际调用链为准，采用可验证且符合项目边界的部分，不按原报告优先级直接改写恢复、安全和供应链规则。

保留当前数据库、单写协调器、独立管理面、单数据盘支持、根 `test/` 布局、自维护 Foundation 和 G4 轮廓实现。未增加原生 App 或 Web 上传、下载、预览，也不引入旧版本兼容层。

## 已实施的改进

### 大候选准备去除重复读取

超过 32 个正文副本时，旧准备路径先完整验证并丢弃证明，再完整验证一遍。删除被丢弃的首轮工作，保留每个正文、块哈希、元数据和持有 inode 的完整检查，并增加最后的磁盘目录与封印身份复核。决定和恢复阶段不减少校验。

定向 33 副本实验的准备读取从 66 MiB 降到 33 MiB，哈希次数从 66 降到 33。小候选阈值与持有证明机制不变。实际耗时只是并行编译、缓存已热的开发环境观察，不能推导整次提交快一倍；见[性能证据](../validation/evidence/performance/payload-preparation-20261023.md)。

### 工作区累计证据容量可观测

新增类型化只读容量查询和管理员界面提示。返回使用量、限额、剩余量、接近限额/耗尽状态；所有计数使用规范十进制字符串。普通主体仅见自身信息，管理员可见全池汇总；查询时依据当前授权，不信任请求参数或过期角色。

错误消息区分全池/主体的记录数与元数据字节限额。未删除终态证据，未改变原始操作 ID、账户、摘要、终态或重试结果。

**这不是退休机制，累计额度仍可能耗尽。** 新接口明确 `automatic_retirement=false`。已有成功重试会依赖完整 Workspace、原 fencing token、请求镜像与规范摘要，不能把终态清单当普通缓存删掉。安全冷分层或额度变更还涉及成员配置锚、恢复与崩溃原子性，需独立设计。

### 服务与前端边界

- Bearer 方案名使用 ASCII 大小写无关比较，令牌字节不变；继续拒绝重复头、空令牌和额外字段。
- 现有内部错误别名、明确 HTTP 状态和诊断遮蔽规则集中登记并测试，不把所有内部码误写成公开 API，也不宣称已完成全量错误枚举。
- 嵌入式 router 与网络 serve 共用管理运行时初始化；保持先校验、serve 先绑定监听再启动后台工作的顺序。
- capabilities 的命名策略与 Unicode 版本引用命名组件常量，避免重复字面量。
- 前端会话迁移与改密操作使用互斥枚举，路由使用封闭 Page 枚举，保留结果未知、撤权、epoch、语言切换与重新加载边界。
- 磁盘列表使用经过校验的类型，删除有当前生产端证据支持的旧 `id` 回退。坏响应不再被静默解释成空 ID 或有效磁盘。

### 文档

修正 monorepo 组件与来源身份说明，移回四章的页脚导航，补术语、API 贯通检查和安全、不覆盖、不输出密钥的操作员示例。明确 Web UI 与受控 HTTP API 范围，以及 Rust 产品逻辑与脚本编排的分工。

评审提到的三个 SMB 历史链接实际是未随仓库保存的生成日志，在 `tests/` 和 `test/` 下都不存在。未把路径机械替换成另一个不存在的地址，也未篡改旧证据；当前验证导航说明缺失材料。

## 未直接采用的建议

- 全量 State 改为持久集合、页级 dirty-key、回执冷分层：方向有价值，但本次只落实已证明等价的局部读取优化，不宣称达到端到端 O(delta)。
- 初始化早期半登记恢复：已有 server intent/ready 和后期完成证明，实际缺口是 ready 之前的部分登记。需要阶段化身份绑定及故障矩阵，不实施自动清盘或只凭 pool ID 续做。
- panic 后 catch_unwind 继续写或自动重开引擎：不能证明损坏不变量已恢复，不采用。报告举出的若干 unwrap/expect 有明确前置条件，不当作已复现外部漏洞。
- 校验失败日志末帧自动截断、旧操作只留 ID+摘要：可能破坏决定、授权和重放证据，不采用。
- 整体回迁 vendor、搬回 Rust 默认测试布局、统一不同来源许可证、删除迁移名称门禁：与现有目标或证据要求不符，不采用。
- 直接引入 SSE、全套 i18n 资源系统、可配置口令强度或更严 systemd syscall/network 策略：需要具体需求和实际兼容/安全验证，不因报告提到就新增机制。

## 验证与发布边界

源码、契约、权限、坏响应与生命周期回归随改动维护，完整 CI 与 Release 工作流对最终发行提交重新验收。具体结果以对应运行和发行说明为准，旧提交或部分定向通过不能替代最终验收。

物理故障、真实 SMB 客户端互操作与长期容量验收仍须按[首发清单](../validation/first-release-readiness.md)执行。已披露的上游许可资料缺口继续保留在[合规说明](../../compliance/README.md)，不因这轮优化而标为关闭。
