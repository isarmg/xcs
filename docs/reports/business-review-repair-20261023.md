# 业务代码重新审查与修复（2026-10-23）

## 范围与方法

以 `dcdd0a00fd803e285d2c825275c01a8d96bdff74` 为审查起点，重新追踪项目业务调用链，而不是把上一轮 foundation 结论当作本轮证据。覆盖 HTTP/认证、管理与恢复、核心存储、SMB/VFS、Web 控制台、公共契约及对应测试。起点 `src/foundation` 以外有 13 个工作区组件、219 个 Rust 文件、92,251 行，其中 Unicode 数据表占较大比例；该统计不是逐行形式化验证或原创代码占比。

审查发现按实际调用链、触发条件和回归场景交叉核对；没有把只读缓存失效、支持范围取舍或本地管理员可修改自己的文件自动认定为远程安全漏洞。修复继续遵守单存储盘可用、Web 不上传/下载/预览、Linux amd64 服务端及浏览器 WASM 的产品边界。

## 修复清单

### 存储与发布

- 磁盘文件管理根原先固定请求三份副本，导致单盘和双盘固定路由首次建目录失败。默认改为明确的一份主盘副本，备份必须显式选择；同时规范化槽位查找。测试涵盖一、二、三盘配置、首次目录/内容保存和重新打开。
- 文件分支归档原先只检查按文件缓存的选择，遗漏同一文件在不同路径的独立上下文。现在检查真实路径选择，并在工作区验证及目录内容同步处拒绝非活动的直接所有者。继承的冻结来源与当前可写所有者仍有区别。
- 同代上传重试原先仅核对新请求与旧清单，可能在旧暂存内容缺失或损坏时返回成功。现在锁外验证保留内容，持有验证的文件描述符，并在接纳时复核文件身份与修改印记；不把新字节偷偷覆盖到原代际。
- 可见的日志帧和不可变对象不等于已经完成持久化。重复发布必须重新完成此前可能失败的文件/父目录同步；恢复修复相同对象时也不能跳过该屏障。故障注入测试验证失败重试不重复追加、不提前返回成功。这不等同于真实断电硬件试验，也不据此宣称已发生数据丢失。
- 在线与离线导出使用保留的源描述符；实际输出的长度、全文摘要及校验清单摘要必须在最终不覆盖重命名前匹配版本承诺。输出变化时不发布成功文件。

### HTTP、认证与管理生命周期

- 显式错误类型的 `commit_id` / `source_commit_id` 不再被当作缺省值而回退当前 HEAD。缺失可以走缺省行为；显式空字符串、null、布尔、数字、数组、对象均拒绝。
- 公共引导请求仅消耗其来源的限流预算；登录、引导和受保护恢复的计数/容量隔离。无凭据请求不再耗尽其他来源管理员的固定窗口恢复预算，昂贵后端工作仍有并发上限。
- 存储重试的认证锁等待和同步工作移出 Tokio 执行线程；许可随真正的阻塞工作持有，HTTP 取消不提前释放。
- 后台原生恢复线程纳入停止与排空所有权；停止后不再新增恢复写者。正常返回、错误、取消以及排队清理任务未执行便被丢弃的情况都保留排空责任。已经持久成功的初始化/恢复不会因为停止时不能再次入队而被误报为失败。
- systemd 仓库模板使用无限停止等待，匹配持久写任务排空语义；管理员仍可显式强制停止，随后按崩溃恢复处理。本轮不操作已部署服务。
- 未验证或离线的成员盘不再通过空挂载点显示系统盘容量；有效成员通过固定目录描述符采集容量。

### SMB 与界面

- SMB 会话携带独立持久绑定代数，后端在与业务操作相同的引擎锁范围内核验共享启用状态、分支及代数。禁用、重新绑定或禁用后重新启用不会恢复旧会话权限。普通目录组成切换不冒充共享重绑定。
- 目录枚举改为句柄拥有的不可变快照与分页游标；页面受条目数和实际编码字节双重限制。服务端从已排序的提交条目借用范围，仅复制当前页，避免每页完整树 JSON 往返；VFS 只缓存一页。旧的无界 List 协议不保留兼容入口。
- Web 详情重命名统一进入已有的分支范围审核与批量命名空间请求，携带稳定条目身份和依据子树；公共单条路径命名空间入口只保留 mkdir。核心 SMB/POSIX 路径语义和已有带前置条件的工作区机制不因此删除。
- 账户写入成功后立即使旧列表失效并重新读取；行点击从最新快照取值，不能把先前撤销的权限用旧行数据重新填回。未知结果仍不能用一次快照刷新代替操作完成证明。
- 原位编辑提交后保留草稿，按原操作回执解除或保留锁定；明确冲突不丢输入，未知结果不允许重复发送。会话/上下文改变时不把旧草稿应用到新对象。
- 别名行选择按完整界面上下文识别，不把共享 entry_id 的所有行一起高亮。

## 契约变化

`Repository.smb_binding_generation` 是必填的规范 UINT64 字符串，新仓库初值为 1。显式共享绑定更新推进该值；拆分禁用源仓库也推进，新拆分/导入仓库保持禁用并建立自己的初值。模型、schema、OpenAPI 镜像与维护向量同步更新。缺失字段的旧持久格式不补默认兼容值。
