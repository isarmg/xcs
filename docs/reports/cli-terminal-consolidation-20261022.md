# CLI similarity and terminal UTF-8 source ownership

These two independent changes are justified by ownership, not a numerical package target.

- command-line absorbs strsim 0.11.1. Jaro scoring is used only by CLI suggestions. The complete reviewed implementation and all 96 retained source tests live together behind a private module. The suggestions feature and confidence threshold/order are unchanged. There is no replacement crate, re-export, forwarding package, registry dependency, or algorithm substitution.
- terminal-style absorbs utf8parse 0.2.2. Its ANSI parser and output-strip adapter now share one private UTF-8 state machine. parser-utf8 remains optional, output still selects it, parser-core remains distinct, and the default style-only graph stays dependency-free. The byte transition machine and its invalid-byte consumption contract are unchanged.
- Trade-offs: the CLI owner retains additional internal metrics to preserve the whole reviewed source/test corpus instead of opportunistically deleting algorithms. This removes two crate boundaries, but does not claim a benchmarked compile-time speedup; modifying CLI code can recompile similarity code rather than reusing a standalone crate. UTF-8 unsafe scalar construction stays inside its private decoder module and is not expanded.
- Test changes: the CLI proof now compiles and counts all 88 upstream unit tests, 8 upstream integration tests, all 11 upstream doctest examples through a private-source harness, and 9 existing suggestion contract tests before running them. Explicit std-only and std+suggestions compilation checks cover the optional feature boundary. The terminal proof counts and runs the retained UTF-8 demo plus both original benchmark bodies as stable smoke tests, and adds exact invalid-sequence callback, split-byte scalar, and clone/resume regressions. Existing native/wasm feature checks, consumer behavior, and CLI output/exit golden checks remain in place. No test exclusion is added.
- Retained-test repair: the new full owning-crate CLI run exposed missing historical test-only dependencies. Four positive `assert_impl_all!` invocations are replaced by direct generic-bound checks for the exact same concrete types and traits (including both unwind-safety traits for `MatchesError`). No negative assertion was changed. The emoji-width test now checks every scalar in the two original ranges instead of filtering for emoji, a strict superset under the unchanged `ch_width(_) == 1` contract. This avoids new dependency packages without weakening any supported assertion. Independent source review confirmed both equivalences.
- Mechanical ownership/lint adaptation: the suggestion parent becomes suggestions/mod.rs because it now owns a child implementation under the owner's existing module-file lint. Display formatting, enum/constructor Self spelling, lifetime elision, and mem qualification are behavior-neutral. The Jaro lower-bound expression becomes saturating_sub, exactly equivalent for all usize pairs to the original subtraction-or-zero branch. No thresholds, comparison order, or metric formulas change.
- Provenance: exact f18c77be current-owner snapshots, all current production/external-test files, every previous merged origin, and immutable predecessor consolidation identities are retained. Redundant helper manifests are archived in the receipts. No origin version, license material, old consolidation receipt, or existing provenance record is rewritten.

## Integration evidence

The reviewed plan is compliance/cli-terminal-consolidation-plan.json. Exact pre-consolidation source archives and SHA-256 sidecars are retained under compliance/command-line-current-sources.tar.gz and compliance/terminal-style-current-sources.tar.gz.

The complete source refresh, metadata verification and no-plan replay preserved all 407 source identities and previous receipt bytes.

All-feature Clippy exits successfully without deny-warnings. There are no warnings in moved or new code; 24 pre-existing CLI documentation warnings and 16 pre-existing terminal warnings remain. No throughput or compile-time improvement is claimed. Final combined CI acceptance is tracked separately.
