# ADR 0004：分页历史清单与增量投影

状态：**实验实现，等待整批 CI 验证，发行格式未冻结**。代码已实现单一当前分页根；未发布项目不设置格式代际或兼容分支；真正的增量投影阶段仍未完成。本文不表示历史写入已经达到 O(delta)，也不代替物理盘验收。

## 背景与目标

原有 `HistoryManifest` 是每棵历史树的完整 JSON。发布前重新构造、校验和编码全部历史清单；历史增长会生成新的完整对象，并可能超过 64 MiB 元数据上限。状态快照已有分页，但根节点仍直接列出全部页面哈希，不能把同一结构照搬为无限容量方案。

本提案保留 SQLite 可重建投影、权威日志、完整正文版本及三成员发布闭包。先解决单树清单的扁平对象增长和结构共享，再独立推进增量投影。不使用 TTL、自动 GC 或未经验证的缓存删除历史成本。

## 选定格式与证据边界

- 候选通过 `history_manifest_hashes: BTreeMap<String, String>` 绑定历史图。映射值始终是 `history-manifest` 域内、由候选直接绑定的对象摘要。
- 存储清单只接受 `PagedHistoryRoot`，包含仓库、历史树及固定字段集合到映射根的引用，不带格式版本号。`HistoryManifest` 只作为展开后的内部逻辑模型，用于语义校验及恢复导入；不能将其作为根对象读取。
- 映射采用按实体键摘要分路的确定性 16 路 Merkle 索引；新 `history-index` 对象保存有界子引用，引用显式区分索引和叶页。叶页可复用现有 `state-page` 的普通 JSON 映射编码及存储规则。内容完全相同才共享对象，不假定历史投影页等于全局状态页。
- 页面最多 128 个条目，多条目页面目标为 64 KiB，分路最大深度 64；这些是版本定义的常量，不由调用时的元数据上限决定。单个较大实体可以独占叶页，保留原有 64 MiB 对象读取上限，再受实际准入上限检查；不能把页面目标误当成更小的实体上限。
- 读取验证每层域哈希、固定对象形状、引用种类、分路前缀、最大深度、重复实体和字段集合；重建后仍执行完整历史语义校验。若记录条目数，必须重新核对，不能把它当作可信分配长度。

候选绑定的根哈希与展开后逻辑 JSON 的哈希是两种身份。不得把后者写入前者的证明字段，也不得在已有候选中替换根来适配新编码器。

## 发布、恢复与旧数据

正常发布先冻结所有叶页、索引和根的规范化字节，再检查每个对象、候选、完整发布证明、本盘证明、历史包组合证明和墓碑的实际大小。检查必须在新正文复制及 PREPARE/ACCEPT 前完成；依赖页、索引和根在决定前按依赖顺序安装到成员。保留准备完成后的状态、配置及正文身份复查。

正常与降级恢复都以原候选的哈希为入口，逐对象从可信成员选择有效副本，可组合不同成员上幸存的不同页面。任何页面都不能靠多数投票、SQLite 内容或另一个根替代。只读选择不顺带修复；修复先验证准确摘要，再复制到相同地址。降级恢复必须在 REPROTECT 前完成依赖检查及组合证明预检，不能因为结果变为降级发布而改写原清单。

当前读取器只接受严格的分页根、索引、叶页及包证明形状，不提供其他格式分支，也不从快照重建扁平根；拒绝不匹配对象时保留已有材料，不执行删除或破坏性迁移。根/索引/叶页缺失全部有效副本时失败关闭，不使用逻辑投影重新定根。读取检查点不得掩盖历史图依赖的缺失或损坏。

当前发布绑定准确分页根；单一格式实现不改写或删除已有对象，也不自动迁移不匹配的磁盘材料。ACCEPT 前崩溃仅可能留下未引用对象；ACCEPT 后沿用未决恢复机制，不自动清理历史。不承诺将当前磁盘材料交给其他形状的二进制读取或回滚。

## 独立历史包

独立包的 `manifest.json` 保存准确的分页根，`publication.json` 使用严格的包证明，另携带全部可达索引、叶页和原有 `versions/` 正文材料。验证链为：

候选与发布闭包 → 候选中的历史根哈希 → 准确根对象 → 全部索引/叶页 → 逻辑清单语义 → 完整正文与校验清单。

`HistoryPackageReport.manifest_hash` 明确表示上述绑定根摘要。若另提供展开的便捷文件，它只是派生结果，必须与图重建结果一致，不能成为权威输入或包验证的必要大文件。

导出选择与当前逻辑历史匹配的有效发布证据，再复制其准确对象图。只导出准确绑定的图和包证明；不匹配对象明确拒绝，不能无新发布就升级证明。离线检查不依赖原池、系统索引或网络。导入先验证全包，再执行现有身份冲突检查、路由重绑定、正文复制及目标池重新发布。

## 实现边界与代价

| 入口 | 必要变更 |
| --- | --- |
| [history_package.rs](../../src/engine/src/history_package.rs) | 严格分页根读取、图准备/遍历/修复；`PackageProof`、大小预检、导出和加载分派；保留逻辑校验与导入规则 |
| [publication.rs](../../src/engine/src/engine/publication.rs) | 准备完整图、冻结准确根、依赖先于决定落盘；不在构造候选后更换根 |
| [recovery.rs](../../src/engine/src/engine/recovery.rs)、[degraded_recovery.rs](../../src/engine/src/degraded_recovery.rs) | 用准确绑定图修复替代调用当前编码器重新生成全部清单；修复去重以对象域和哈希共同为键 |
| [publication_evidence.rs](../../src/engine/src/publication_evidence.rs) | 逐依赖、跨可信成员的只读哈希验证，不要求单个成员拥有完整图 |
| [metadata_budget.rs](../../src/engine/src/metadata_budget.rs)、[journal.rs](../../src/engine/src/journal.rs) | 精确计入新图对象和包证明；复用冻结字节和候选闭包；保留准确快照读取 |
| [object_storage.rs](../../src/engine/src/journal/object_storage.rs)、[recovery_checkpoint.rs](../../src/engine/src/engine/recovery_checkpoint.rs) | 复用安全地址、哈希前缀/原子写规则；验证新依赖纳入检查点覆盖 |

仅分页后，State 克隆、快照全量遍历、各历史投影构造、索引差分和现存对象碰撞校验仍可能是 O(total) CPU/I/O；保存全部准备字节也仍消耗与图规模相关的内存。结构共享降低新增落盘字节，不等于端到端 O(delta)。

真正的增量阶段需要穷尽的类型化字段投影、可信变更集及归属反向关系，覆盖版本/文件、分支、目录、选择项、路径节点和仓库策略。移动、删除、拆分必须处理新旧归属；仓库级变化可能影响多棵历史树。仅改变的投影条目进行路径复制，并以全量 `HistoryManifest::from_state` 为差分校验基准。派生状态须由权威证据重建，不能把 SQLite 变为依据。减少完整性读取还需要单独论证可验证的复用条件。

本阶段仍保留单个大型实体（尤其 `Commit.entries`）、候选中的全部历史根映射、快照根引用和组合证明的上限。扩大这些边界需要后续格式设计；此实现不宣称无限历史容量。

## 分阶段验收

| 阶段 | 必须成立的测试 |
| --- | --- |
| A：格式与预检 | 扁平投影及未知字段拒绝且不重写；当前候选和证明身份保持；分页根确定性、可选字段和大整数编码；固定分区规则下多页清单超出单一扁平上限仍可处理；超大实体、候选、根或证明在正文复制及日志推进前拒绝 |
| B：恢复与迁移 | 扁平投影误作根时拒绝；当前未决候选正常/降级恢复；根/索引/叶页单副本损坏可修复，全部缺失失败；不同成员缺不同页仍逐对象恢复；错误引用种类、重复实体、非法前缀/深度及跨历史内容拒绝 |
| C：独立证据 | 替换其他有效包的根或页失败；展开文件不能改变恢复结果；删除原池及 SQLite 后离线检查/导入；完整正文、墓碑、路由重绑定与重新发布保持语义 |
| D：耐久边界 | 图安装、PREPARE、ACCEPT、正常及降级发布各故障点；检查点不隐藏损坏；哈希前缀对象修复；真实设备掉电/拔盘另行验收 |
| E：增量与规模 | 插入/修改/删除仅改变相关路径，无关历史根不变；拆分、迁移和间接归属变化对照全量投影；分别记录新增字节、遍历/编码次数、内存及验证 I/O，不以共享页面数量替代端到端性能数据 |

本地软件回归已覆盖版本读取、准确根绑定、普通/降级修复、只读跨副本选择、包替换拒绝与大小预检；CI 和实际设备验收分别记录。超过真实 64 MiB 的测试是合成编解码容量夹具，不代表完整语义历史或真实存储性能。E 的增量与规模结论单独报告，不能用已有页共享替代。

## 替代方案与依据

直接增大元数据上限保留整树重写和内存风险；仅使用 快照式平面页引用把上限移到根；用全池快照替代独立历史包会扩大披露范围和依赖。这些方案不作为本阶段选择。
