## 1.1 功能要求

| 编号 | 要求 | 本文落实方式 |
| --- | --- | --- |
| R01 | 用户分配 n 块硬盘的存储与备份职责 | m 块一级盘、c 块二级盘及后续各级盘分别登记；每盘独立 Btrfs，剩余盘可保留为未分配或备用 |
| R02 | 按重要性保存 1～N 份且备份来源确定 | 第一份固定一级盘，后续每份沿用户指定的逐级来源映射保存；不从存储池任意选盘 |
| R03 | 单盘可独立恢复本盘持有的版本 | 每个有效副本都是完整普通文件，校验和恢复不需要其他版本或另一块盘补齐内容 |
| R04 | 文件更改后只允许全量保存 | 每次完成保存创建新的完整版本；已有版本不原地修改 |
| R05 | 从文件历史版本继续保存时创建文件分支 | 仅登记冻结父版本，不复制正文或建空文件，首次实际写入形成独立 FULL；目录分支组合共享文件分支 |
| R06 | 采用 SMB 提供独立基础访问 | 服务端使用 Samba，SMB 作为独立协议入口接入统一存储核心，不开发客户端虚拟磁盘驱动 |
| R07 | 本机 Linux 也遵守统一业务规则 | 本机通过桌面 App、SMB 或管理接口访问，底层盘不向普通应用开放 |
| R08 | SMB 只提供最基础的功能 | 浏览、打开、新建、编辑、复制、移动、改名和删除当前文件；保存直接进入共享对应的主分支 |
| R09 | 六平台均提供自行实现的 App | 自行开发 Linux、Windows、macOS 桌面 App 及 Android、iOS、iPadOS 移动 App，全部通过统一业务接口访问；六平台另提供独立 SMB 访问入口 |
| R10 | 六平台统一命名 | PortableName/PortablePath，服务端最终校验 |
| R11 | 非法名字明确报错 | 不静默改名、截短或忽略导入项 |
| R12 | 支持按需读取 | 完整文件支持范围读取，不统一强制先下载整个文件才能打开 |
| R13 | 文件内容仅 FULL，目录分支由不可变子树演进 | 显式创建才增加命名分支；修改或切换子项增加子树；文件合并选择结果及归属，同步相关目录，目录合并待确认 |
| R14 | 历史文件内容可删除，历史树不消失 | 清除内容与删除拓扑分开；提交、父边、名称、版本摘要及删除标记继续可见 |
| R15 | 历史树可以拆分 | 在选定提交切开，迁移其全部后代；两树拥有独立元数据和文件，分别管理和恢复 |
| R16 | 完整设计与验收材料 | 提供功能规则、架构图、接口、配置、故障处理和验收标准 |
| R17 | 多次备份盘的来源由用户指定，关系类似树 | 每个二、三、四级备份盘明确列出上一级来源；备份映射与历史树分开 |

## 1.2 功能规则与术语

本项目自行实现六个平台的客户端 App，通过统一业务接口提供文件操作与获授权的高级功能。SMB 是独立的基础文件访问入口，使用用户选定的默认根目录组合。两种入口分别连接服务端，在统一存储核心执行相同的权限、保存和备份规则。所有实际内容版本均为 FULL；新分支先建立记录和来源引用，实际写入才生成独立完整版本。文件分支合并会采用用户指定节点并推进归属分支及相关目录引用；旧关系画线另以 MergeLink 保存。历史内容可以清除而保留结构；历史树拆分目标及当前实现边界见实现记录。

| 概念 | 定义 |
| --- | --- |
| 全量保存与文件分支 | 创建只引用冻结来源；首次实际写入才建立独立完整版本，不重写其他文件 |
| 目录分支 | 稳定命名对象组合共享文件分支；创建只引用父内容，修改保存不可变子树，切换预检范围后一次发布 |
| 文件容器 | 展示的文件实际上是保存各完整版本的真实目录，改名修改容器名，下载任一版本采用容器当前名称 |
| 主分支与其他分支 | 默认根目录组合可由有权用户切换；SMB 新操作使用该组合，旧读取固定版本，相关旧写会话冲突并保留暂存 |
| 浏览历史与保存历史状态 | 浏览不产生分支；从历史节点建立待写入分支，实际保存的文件才产生新完整版本，不能改写旧节点或覆盖主分支 |
| 文件分支合并 | 输入明确的分支头、任意同文件结果节点和归属；结果复用原头或新增元数据子节点，其他输入成为只读别名；[完整规则](design/file-merge-tags-backup.md) |
| 关系标记 | 旧 MergeLink 仅保存固定端点关系，不推进 HEAD，与实际文件合并分别管理 |
| 节点标签 | 标签属于具体文件节点，子节点继承；标签修改新增元数据子节点，支持批量，不回退历史正文 |
| 历史树与目录树 | history_tree_id 是独立历史及内容管理域；tree_id 是快照；文件混合节点允许无环多父关系，Commit 谱系与旧关系标记分别管理 |
| 历史内容清除与历史树删除 | 清除 payload 后节点标记 PURGED；不移除提交、父边或目录快照描述 |
| 拆分与创建分支 | 分支仍在同一历史域；拆分得到两个独立历史域、独立文件和恢复包 |
| 全量保存与备份份数 | 一个完整版本可以保存一份、两份或更多份；每份均完整，按用户指定的物理盘路由计数 |
| 备份拓扑与历史树 | 备份拓扑记录盘位来源，历史树记录版本演进和合并标记；两者分别管理 |
| 份数与备份次数 | 第 1 份为一级原始存储，第 2 份为首次额外备份；保存两份总共占两个指定物理盘 |

## 1.3 系统定位与边界

本系统是单台 Linux 服务器上的版本化文件服务。自研桌面 App 和移动 App 通过业务 API 提供文件操作及获授权的高级管理，独立 SMB 入口提供主分支基础文件操作，网页和 CLI 提供管理及自动化入口。第一版不提供多服务器自动选主、跨机双活、NFS/WebDAV、通用数据库文件系统或无条件离线自动写回；不提供普通操作中的 rebase、强制 HEAD 重置或静默冲突覆盖。

n 由已登记物理盘决定；采用三成员元数据保护，要求至少三个不同设备，数量不足时不开放受保护写服务。业务内容的目标份数 r(v) 受其一级盘可达备份链深度限制；实际提交要求链上前 r(v) 个指定盘位全部可用且持有完整文件。三份控制元数据不等于每个业务文件必须保存三份。

<a id="s01-04"></a>

## 1.4 单盘与跨平台兼容性

命名兼容、SMB 客户端兼容和拆盘后的文件系统兼容分别验收。独立 Btrfs 的标准离线恢复环境为支持对应版本的 Linux。有效内容副本是可直接读取的完整文件，恢复不依赖旧版本。六平台在线接入不等于六平台插入 Btrfs 盘即可原生读取。

单盘只恢复该盘实际持有且校验有效的文件，不保证包含整个仓库或最新全局历史。禁止通过硬链接、reflink 或跨树去重伪装完整文件的物理独立性。

## 1.5 系统能力与数据接入

| 领域 | 方案 |
| --- | --- |
| 自研 App | 本项目自行实现六平台客户端，包含界面、连接、认证、文件操作、缓存和任务状态，通过业务 API 访问 |
| SMB 访问 | 独立于 App 的标准协议入口，由 Samba 提供共享主分支的基础操作 |
| 高级管理 | 桌面 App、移动 App、Web、CLI 共用业务契约，按账户权限开放功能 |
| 保存与分支 | 内容仅 FULL；分支创建只记录和来源引用，首次写入形成正文；目录分支递归批量操作，历史另存仅保存工作区实际写入文件 |
| 合并标记 | 仅记录两个指定版本之间的连线，不创建内容版本或改变分支 HEAD |
| 放置策略 | 用户指定一级盘及逐级来源、目标；迁移已有版本须显式执行 |
| 持久化 | 两成员形成决定，三成员保护齐全后正常发布和成功确认 |
| 命名 | PortableName/PortablePath，固定 Unicode 16.0.0 数据 |
| 内容保留 | 默认不自动清除；显式清除保留历史拓扑和删除标记 |

接入外部数据前，先只读识别格式、内容完整性和实际位置，再导入为完整文件。依赖式存储须先还原并校验完整字节；缺失内容保留真实状态。完成完整性、放置和恢复验证后，才开放相应写入及源材料清理。
