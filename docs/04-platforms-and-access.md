## 4.1 支持矩阵

六个平台的 App 均由本项目自行开发，通过统一业务 API 使用文件及高级功能。SMB 是另一个独立入口，桌面和移动端均可通过该入口访问主分支基础文件。App 与 SMB 不共用客户端模块、连接或工作区。

| 平台或入口 | 访问实现 | 功能范围 | 保存规则 |
| --- | --- | --- | --- |
| 服务器本机 Linux App | 本项目自研 Linux 桌面 App，经业务 API 连接 | 文件操作与获授权的高级功能 | 保存至明确选定分支；历史另存登记新分支，仅实际写入产生 FULL |
| 远程 Linux App | 本项目自研 Linux 桌面 App，经业务 API 连接 | 同上 | 同上 |
| Windows App | 本项目自研 Windows 桌面 App，经业务 API 连接 | 同上 | 同上 |
| macOS App | 本项目自研 macOS 桌面 App，经业务 API 连接 | 同上 | 同上 |
| Android App | 本项目自研 Android App，经业务 API 连接 | 同上 | 同上，后台执行按系统适配 |
| iOS App | 本项目自研 iOS App，经业务 API 连接 | 同上 | 同上，后台执行按系统适配 |
| iPadOS App | 本项目自研 iPadOS App，经业务 API 连接 | 同上 | 同上，后台执行按系统适配 |
| SMB（桌面及移动端） | 独立 SMB 协议连接至 Samba | 浏览、打开、新建、编辑、复制、移动、改名及删除当前文件 | 共享绑定稳定主命名空间，按用户选择的默认目录组成和文件引用保存 |
| 管理网页 | 本项目实现的 Web 界面，经业务 API 连接 | 文件操作及获授权的高级管理 | 保存至明确选定分支；历史另存登记新分支，仅实际写入产生 FULL |
| 管理 CLI | 本项目实现的命令行工具，经业务或受保护本机接口连接 | 文件操作、自动化管理及状态查询 | 遵守相同的权限、分支和保存规则 |

<a id="s04-02"></a>

## 4.2 SMB 只提供基础文件能力

SMB 提供浏览、打开、读取、新建、编辑、复制、移动、重命名、删除当前文件，以及必要锁与错误返回。通过 SMB 保存进入共享主命名空间所选的默认目录组成，按该文件的继承意图或明确分支写入，后台按全量版本和指定备份路由处理。

SMB 协议不提供分支选择、历史图、版本比较、历史内容清除、合并、树拆分或硬盘分配。App、Web显式改变共享默认目录组合或其文件引用时，后续SMB操作使用新组成，但不更换共享绑定，既有句柄仍受原读取版本或写入基线约束。旧 `MergeLink` 只标记关系；文件分支合并 `FileBranchMerge` 可采用已有正文并推进参与目录引用，随后SMB读取相应新组成，见[合并规则](design/file-merge-tags-backup.md)。

SMB 删除仅删除主分支当前目录项，不能解释为清除其历史内容。SMB 不发布可写历史快照目录，也不以特殊文件名开放高级管理。

<a id="s04-03"></a>

## 4.3 桌面 App、移动 App 与 SMB 的职责

Linux、Windows、macOS 提供本项目自行实现的桌面 App；Android、iOS、iPadOS 提供本项目自行实现的移动 App。两类 App 均提供基础文件管理、预览、历史查看、分支创建与首次写入、旧关系标记、文件分支合并、历史内容清除、树拆分及按权限开放的备份和维护功能；目录分支合并待用户确认，暂不实现。

App 通过业务 API 访问完整功能，工作区明确绑定历史树和分支。SMB 通过独立协议入口访问共享主命名空间。工作区自身的分支绑定与共享默认选择分别管理；显式修改共享目录或文件引用可以影响后续SMB视图。两个入口分别管理连接和工作状态，服务端统一仲裁并发访问。网页和 CLI 遵守相同权限规则。

不同系统的文件交接、外部编辑器、本地缓存和后台执行能力分别适配与验收。桌面与移动 App 均需保留未保存修改并展示服务器保存状态；移动端后台限制按系统说明，不要求 root 或越狱。

<a id="s04-04"></a>

## 4.4 按需打开与外部应用

SMB 基础读取及 App 内容接口支持按范围请求。App 内播放器、预览和大文件查看器可按需获取内容。

外部编辑器或文件解析器可能需要完整本地文件，按其实际机制提供并显示获取进度。系统不能保证所有文件类型、所有客户端都实现流式打开。

App 管理自己的读取缓存、未保存修改和操作状态，断网时只使用已有且有效的缓存内容并保留修改。SMB 的连接状态由独立入口处理，服务端保留已接收但未确认完成的工作数据。两个入口都以服务器结果判断保存是否完成，重连后先核对原操作和基础状态。
